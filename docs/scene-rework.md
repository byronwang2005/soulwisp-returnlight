# 场景与跨区训练

人物保留 KayKit 风格，身体从脚底到头顶为约 2.2 渲染单位。职业差异由轮廓、武器和配色体现，帽子、披风和装备不参与身体测量。缩放在模型根节点执行，职业移动速度、攻击距离和库存规则沿用服务端规则。罩帽斥候以同包无罩帽 Rogue 的身体作为参照。

`node scripts/scene-assets.mjs --record`重新核验九个职业的身体尺度和脚底偏移，结果写入[尺度记录](verification/character-scale.json)。高画质 DPR 跟随设备，上限 2；镜头缩放为桌面 50、手机 42，使身体投影约为桌面 84、手机 71 CSS 像素。

## 地图与铺装

[共享场景配置](../packages/shared/src/scene.ts)定义世界单位换算、人物半径、站点占地、道路半宽和材质世界尺度。正式地图为每章和撤离祭坛预留独立槽位，站点沿区域外侧扇形排列。归灯堂按连接方向旋转四个站点，避开入口；扩大放不下的区域并拉开间距，保留双环连接。实体占地与人物半径参与服务端通行判断，物件前保留接近位置。`GameView.edges`随授权地图一起发送，小地图、教程导航、连续铺装和服务端通行判断使用相同连接。

区域边界用 128 段圆周近似，最大边界误差小于 0.1 个世界单位。房间先做并集，道路并集扣除房间，生成两个无重复叠面的静态网格。UV 来自世界坐标，不随道路长度拉伸。石面颜色降低饱和度；裂缝、污垢及石砖接缝均来自材质。1K / 2K 颜色、OpenGL 法线、ARM 贴图配置颜色空间、mipmap 和最多 8 倍各向异性过滤。来源、许可与恢复命令见[资产许可](asset-licenses.md)。

普通区域与道路删除所有柱圈及固定模型柱。归灯堂和城门的后侧背景最多放两根建筑柱，柱子及人物半径外扩范围不进入可走区域，放不下即省略。公共仓库用金色箱体，寄存箱用较小普通箱体；降蚀台为青灰十二边台，净化台为金灰六边台，四处都有用途标签。重复静态箱体按资产合批为 InstancedMesh，共享几何、材质与贴图。

区域外侧用批处理的低石岸、苔藓和后侧残墙衔接背景，避开全部区域及道路外扩范围；近处石岸低于角色，远处残墙建立旧城轮廓。

## 动作

服务端持有最后朝向，并生成 `SelfView.actions`，包含目标、动作、距离、可执行状态和阻止原因。客户端交互按距离、朝向、稳定 ID 选择，新目标至少近 10 个世界单位才切换，失效或离开范围时立即释放。读条固定目标，服务端在完成时重新校验。

攻击从前方 120 度和原攻击距离内寻找守卫，再找显形角色及普通玩家。护盾、救援、开箱和修护按职业用途独立寻找目标；交接保留双方确认。隐藏角色不发送坐标或朝向。动态掉落尽量在附近可走位置分开摆放，资源和物品实例仍由服务端分配，争抢只产生一次拾取。

WASD、方向键和触屏按钮按镜头方向移动。连接道路中，输入与道路方向接近时沿道路导向并纠正轻微偏移；横向转向立即释放导向，区域内部完全自由移动。服务端仍按原职业速度和通行范围校验。角色头顶五瓣心灯每瓣代表 20 点生命，部分心瓣随生命逐渐耗尽，低生命闪动，倒地显示救援提示；左下血条删除，治疗按钮独立保留。教程头部采用固定徽标与短按钮，保存离开保留完整可访问名称。

## 六课与续学

五区训练复用 GameEngine、地图连接、动作候选与正式读条。除正常议会回堂外，下一课保留人物所在位置。任务由成功动作及实际状态判断；人类和蚀月者均需完成采集、开箱、交付、寄存、两次点灯、守卫战、救援、补给、降蚀、证据、表决、祝福、灯芯净化与八秒守圈。蚀月者另需显形、腐化及灰雾。

账户六阶段进度与一次完成奖励接口沿用现有实现，无数据库迁移。续学根据已经完成的阶段重建库存和训练状态，当前课重新完成。

## 自动画质和复验

复用 Drei PerformanceMonitor，以 2.5 秒为窗口。连续两个窗口低于 57 FPS 降一级；连续达到 59 FPS 十秒后试升一级，失败的升档三十秒后再试。五级依次降低阴影分辨率、阴影与装饰、贴图与 DPR、法线；最高级不设应用帧率上限。加载后预热三秒；隐藏页面暂停渲染与采样，恢复时重置窗口并重新预热。服务端模拟频率不随渲染频率变化。

```sh
npm ci
npm run check
node scripts/ground-assets.mjs
node scripts/scene-assets.mjs
npm run build
```

使用 Node.js 24。集成测试需 PostgreSQL 与仅绑定环回地址的本地 LiveKit。浏览器教程测试只读取授权视图进行导航，用键盘或触屏按钮执行动作。十人 GPU 场景是十个职业席位的规则引擎渲染夹具；真实网络与奖励由实时集成测试另行验证。原生性能记录由选择性启用的测试写入 `docs/verification/scene-gpu-*.json`，覆盖至少两分钟的完整教程与十人场景，并记录 FPS、P95 帧时间、档位、DPR、绘制调用及 GPU。

当前默认仅做静态验证：Node.js 24 类型检查、生产构建、人物尺度、地面哈希和许可清单检查。浏览器、实时联机和 GPU 测试保留为显式请求时使用的工具。历史性能记录标注其验证时间和版本范围，不作为后续改动的自动验收结论。

授权位置使用 80 毫秒缓冲在相邻快照间插值，不向最新坐标外推，传送时清空缓冲。镜头位置与注视点共用角色当前渲染位置，角色每帧插值完成后更新镜头，固定镜头方向与距离。受击抖动同时作用于位置和注视点，不积累偏移。守卫复用已校准的 KayKit Knight 骨骼模型，用红色盔饰、暗铜护甲、戒备姿态和受击动画区别玩家；加载失败时使用人形备用模型。动态守卫不参加静态场景合批。
