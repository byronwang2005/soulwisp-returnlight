# 灯下等待区

在“远征大厅”页面点击“加入等待区”。大厅直接显示候选席位、候场队列、职业偏好、准备人数和游玩区状态；底部提供准备、语音与离厅操作。营地中仍可打开紧凑的等待面板。所有成员进入同一个等待区，按入厅顺序候选；语音默认静音，可自行开麦。浏览营地、收起面板不退出等待区，进入训练、退出账户或点击“离开等待区”会退出。麦克风权限被拒绝或语音离线时，仍可准备和参加游戏。

## 准备与候场

前 10 位等待成员为下一局候选，至少 4 位候选全部准备后，服务端倒数 10 秒。实际候选人数自动决定 4–10 人规则，无需房主、邀请码或手选人数。倒数开始后冻结名单，新成员继续候场；名单内有人取消准备、离开或断线则取消倒数，按当前队列重新检查条件。

超过 10 人仍可进入等待区并连接语音。面板显示候选／候场、准备状态、职业偏好和候场位置；候场成员未准备不影响前面的候选。游玩区同时只能运行一局，游戏进行时等待区继续开放。

职业偏好可以选择一个职业或“随意”。系统先抽签满足职业池中可用的偏好，再随机分配剩余席位。进入游玩区后有 45 秒查看职业、选择技能形态，职业不可更换；之后服务端独立随机分配秘密身份并开始探索。10 人局包含两个灯卫席位。

所有席位连接成功才启动职业准备；转场超过 30 秒未完成则全批回厅并清除准备状态。最终结果公布后展示 15 秒，再自动回厅；也可提前返回。返回者按本批原顺序追加队尾，保留偏好并重新准备，已候场成员排在前面。同批队列位置以第一位成员回厅时为准，后续成员返回时补入原顺序。结算尚未写入时显示“奖励待入库”，写入成功后刷新营地，不阻塞回厅。

## 语音与恢复

等待成员和队列由游戏服务端记录，语音成员不决定准备资格。等待语音无固定人数上限，单局最多 10 人。进入游玩区会停止等待语音，服务端移除成员并撤销旧票据；定期清理持旧票据重新进入的对局成员。议会仍使用独立媒体房、分席发言和每章独立令牌，候场者不能收听。

回厅自动恢复此前已加入的收听连接，麦克风保持静音。浏览器阻止自动播放时点击“点击启用声音”。“关闭收听”只关闭本人的播放；首次开麦后，静音保留设备并停止发送，离开等待区释放设备。

等待连接断开立即清除准备和排队位置，恢复后排到队尾。同账户只允许一个大厅控制连接；恢复对局仍使用原游戏席位及现有 60 秒恢复窗口，超时整局无效。服务重启重新建立大厅、清空准备和倒数；仅清理本部署准确标记的旧媒体房。

## 接口与媒体

| 接口／消息 | 权限 | 行为 |
| --- | --- | --- |
| `GET /api/lobby` | 公开 | 等待人数、游玩区摘要、倒数和维护状态；不返回成员名单 |
| `POST /api/lobby/join` | 账户会话 | 为唯一 Colyseus 等待房预留账户席位 |
| `lobbyView` | 大厅连接 | 本人区域、等待成员、偏好、准备状态、队列位置和公共阶段 |
| `lobbyCommand` | 大厅连接 | `ready` 修改准备；`preference` 修改偏好并取消准备 |
| `matchSeat` | 被选中的账户 | 服务端签发本局预留席位，客户端消费预留，不自行创建房间 |
| `returnEarly` | 本局成员 | 最终结果公布后提前返回等待区 |
| `returned`／`returnToLobby` | 本局成员 | 服务端回厅通知及游戏连接释放 |
| `GET /api/voice/lobby` | 公开 | `available`、语音人数、`capacity: 0`、`url`；0 表示无固定人数上限 |
| `POST /api/voice/lobby/token` | 等待中的账户 | 20 秒媒体票据、`url`、`epoch` |

媒体票据仅允许麦克风和订阅，禁止视频、屏幕和数据发布。不在等待区返回 `403 NOT_WAITING`，对局成员不能拿等待语音票据；语音离线返回 `503 LOBBY_UNAVAILABLE`。

复用现有 Colyseus（MIT）和 LiveKit SDK（Apache-2.0），不新增依赖。语音沿用 Opus 单声道、DTX、RED、回声消除、降噪、自动增益及原连接诊断。`room.auto_create: false` 保持关闭；旧票据不能创建新房。

## 验证

默认使用 Node.js 24 执行以下静态与模拟验证：

```sh
npm exec vitest run tests/client-lobby.test.ts tests/lobby-coordinator.test.ts tests/waiting-room.test.ts tests/voice-lobby-service.test.ts tests/room-voice-gate.test.ts tests/rules.test.ts
npm run check
npm run build
```

发布排空只把转场和对局计为游玩区占用，另行报告待写入结算数；自动发布等待两者归零再备份和切换进程，避免中断奖励重试。

模拟覆盖 4–10 人开局、超员候场、名单冻结、倒数取消、重复账户、授权席位、转场失败、职业冲突、私密身份、15 秒回厅、结算待写入、语音撤权及维护排空。真实 PostgreSQL／LiveKit 联机与浏览器测试需明确要求后执行。

旧的 `verification/voice-lobby-local.json` 是邀请码时期的历史语音报告，不代表本次大厅流程的联机或设备验收。
